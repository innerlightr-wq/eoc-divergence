# Reproducing the pointwise-discovery audit

Everything is exact integer arithmetic; floating point appears only in reported
logarithms and statistics, never in a decision.

## Dependencies — and a deviation from the rest of the repository

`eoc.py`, `words.py`, `pmass.py`, `verify_core.py`, `check_sampler.py`,
`v_structure.py`, `gen_words*.py`, `merge_scan.py` and `depth_scan.c` are
**standard library / plain C only**, like the other audits.

The analysis scripts `m2`–`m9` and `figures.py` use **numpy**, and `figures.py`
additionally uses **matplotlib**. That is the only place in this repository that
depends on a third-party package, and it is deliberate: those scripts do bootstrap
resampling and rank statistics over tens of millions of rows. Nothing in
`Divergence`, `Occupation`, `Descent`, or any other audit depends on them, and no
claim in [`../REPORT.md`](../REPORT.md) rests on a floating-point decision.

## Working layout

The scripts were written against, and are committed exactly as run with, a scratch
working tree rooted at this `scripts/` directory (run everything from here):

```
results/scan_<tag>/part_*.txt     raw output of depth_scan   (~1 GB; not committed)
results/words/<map>_n<N>.csv      sampled word datasets      (~140 MB; not committed)
results/*.txt, *.json             the measurement outputs    (committed, in ../data)
figures/*.png                     the figures                (committed, in ../figures)
```

Only the last two rows are committed; the bulk scans and word samples are
regenerated by the commands below in about 20 minutes on 8 cores.

## Commands

```bash
python3 -m venv .venv && ./.venv/bin/pip install numpy matplotlib
gcc -O3 -march=native -o depth_scan depth_scan.c
mkdir -p results/words figures

./.venv/bin/python verify_core.py        # 13/13 against eoc-divergence's published values
./.venv/bin/python check_sampler.py      # 11/11 sampler and counting-bijection gates
./.venv/bin/python v_structure.py        # the exact realizer identities R1, R2

./run_scan.sh 3  1 32 260 900 A32        # ~20 s on 8 cores
./run_scan.sh 3  1 36 140 900 A36        # ~6 min
./run_scan.sh 3  1 32 100 900 A32deep
./run_scan.sh 3 -1 28 280 300 B28
./run_scan.sh 3 -1 32 140 400 B32deep
./run_scan.sh 5  1 28 280 300 C28
./run_scan.sh 5 -1 32 380 900 E32
./run_scan.sh 5 -1 32 140 900 E32deep
./.venv/bin/python merge_scan.py results/scan_A32     # and likewise per tag

./.venv/bin/python gen_words.py          # ~2 min, 25 word datasets
./.venv/bin/python gen_words2.py

for m in m1_lambda_grid m1b_bitlength m2_delta_law m3_dependence m3b_tail \
         m4_integers_vs_words m4b_envelopes m4c_extended m4d_strata m4e_roots \
         m5_5x1_ladder m6_tail_propagation m7_exact_letter_law \
         m8_aggregate_letters m9_controls m9b_capture; do
  ./.venv/bin/python $m.py > results/$m.txt
done
./.venv/bin/python figures.py
```

Measured peak RSS: 18 MB for the deepest transfer table (`n = 300`), 12 MB for the
`5x-1` mass series to `N = 366`. The `depth_scan` overflow guard (`2^118`) fired
**0 times in all eight scans**, so every recorded depth is exact, not a lower
bound; `merge_scan.py` reports the count.

## Provenance

`depth_scan.c` is adapted from
[`../../cross_map/scripts/scan_rare.c`](../../cross_map/scripts/scan_rare.c)
(same repository, Apache-2.0): the first-step sieve is removed entirely — the scan
steps by 2 over every odd seed — and a per-bit-length depth histogram, a chain-root
histogram and a guard counter are added. Removing the sieve is what exposed the
`q > 4` sieve defect; see
[`../../cross_map/CORRECTION_2026-09-25.md`](../../cross_map/CORRECTION_2026-09-25.md).
Everything else here is new.
